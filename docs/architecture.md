# Архітектура CarRental

## 1. Шари

| Шар | Проєкт | Відповідальність (одне речення) | Що йому заборонено |
|---|---|---|---|
| Домен | `CarRental.Domain` | Сутності, стани договору, профільне правило розрахунку й власні винятки. | знати про файли, консоль, JSON, журнал та інші шари |
| Прикладний | `CarRental.Application` | Сценарії UC-01…UC-06, барикада валідації вводу та інтерфейси сховищ. | знати про формат зберігання і про консоль |
| Інфраструктура | `CarRental.Infrastructure` | Файли JSON, перетворення записів на сутності й журнал у файл. | містити правила домену |
| Застосунок | `CarRental.ConsoleApp` | Меню, читання вводу з повтором, форматування виводу й композиційний корінь. | містити розрахунки й правила |
| Тести | `tests/CarRental.Tests` | Модульні тести всіх шарів, тестові дублери, перевірка правила залежностей. | потрапляти в робочу збірку |

## 2. Правило залежностей

Рисунок 1 — Схема залежностей проєктів:

```
  CarRental.ConsoleApp ──────► CarRental.Application ──────► CarRental.Domain
          │                            ▲
          │                            │
          └──────► CarRental.Infrastructure
```

- **ConsoleApp → Application:** меню викликає сервіси сценаріїв і нічого не рахує саме.
- **ConsoleApp → Infrastructure:** лише композиційний корінь створює JSON-сховища й файловий журнал.
- **Infrastructure → Application:** сховища реалізують інтерфейси `IRentalRepository` і `IFleetCatalog`,
  оголошені в прикладному шарі, тож прикладний шар не знає, де лежать дані.
- **Application → Domain:** сервіси створюють договори й викликають їхні переходи та профільне правило.
- **Domain → нікого:** у `CarRental.Domain.csproj` немає жодного посилання на проєкт чи пакет.

Правило закріплено двічі:

1. **Компілятором.** Посилання між проєктами існують лише за стрілками схеми; якщо в домені написати
   `using CarRental.Infrastructure;`, рішення не збереться.
2. **Тестом.** `DependencyRuleTests` перевіряє посилання збірок: домен не посилається на проєкти
   CarRental, `Microsoft.Extensions.*` і `System.Text.Json`, прикладний шар — на інфраструктуру.

Якщо дозволити зворотну стрілку (домен → інфраструктура), правило розрахунку почне залежати від
формату файлу: зміна JSON на CSV зачепить домен і його тести, а тестові дублери стануть неможливими.

## 3. Композиційний корінь

Єдине місце, де створюються конкретні реалізації, — верхні оператори `Program.cs`
(`src/CarRental.ConsoleApp/Program.cs`). Решта класів отримує залежності через конструктор і
знає лише інтерфейси. Тому заміна сховища чи правила штрафу — зміна одного рядка тут, а не пошук
`new` по всьому коду; тести збирають ті самі сервіси з дублерами (`FakeRentalRepository`,
`FakeCatalog`, `FixedClock`).

```csharp
var catalog = new JsonFleetCatalog(dataDirectory);
var rentals = new JsonRentalRepository(Path.Combine(dataDirectory, "rentals.json"));
var calculator = new RentalChargeCalculator(new StandardLateFeePolicy());
var io = new ConsoleIo(Console.In, Console.Out);
var rentalScreens = new RentalScreens(
    io,
    new ReservationService(rentals, catalog, clock, logs.CreateLogger<ReservationService>()),
    new HandoverService(rentals, calculator, clock, logs.CreateLogger<HandoverService>()),
    clock);
```

## 4. Обробка помилок

| Клас помилки | Приклад | Як подається | Хто показує |
|---|---|---|---|
| Некоректний формат вводу | «abc» замість номера | повтор запиту, не виняток | `ConsoleIo` |
| Відмова за даними | авто немає, період зайнятий | `Result.Fail` з поясненням + Warning у журнал | сервіс → екран |
| Порушення правила домену | закрити договір у стані Reserved | `InvalidRentalStateException` + Warning | `MainMenu` |
| Помилка програміста | нульова ціна доби | `ArgumentException`, падає гучно | — |
| Збій даних | пошкоджений `rentals.json` | `InvalidDataException` + Error у журнал, код виходу 1 | `Program` |

Барикада: ввід з консолі перевіряється за форматом у `ConsoleIo`, а за змістом — рівно один раз у
`ReservationService.Reserve` і `HandoverService`; дані файлів — у `JsonFleetCatalog`. Усередині
домену повторних перевірок немає, лише захист від помилок програміста.

## 5. Точки розширення

| Передбачувана зміна | Механізм | Що змінюється |
|---|---|---|
| Новий вид штрафу (наприклад, погодинний) | стратегія `ILateFeePolicy` | новий клас-реалізація + один рядок у `Program.cs`; калькулятор і тести наявних правил не змінюються |
| Зберігання в CSV або іншому форматі | інтерфейс `IRentalRepository` | новий клас в інфраструктурі + рядок у `Program.cs`; сервіси не змінюються |
| Новий стан чи подія договору | таблиця рішень `RentalTransitions` | рядки словника переходів і значення переліку; методи `Rental` не змінюються |
| Інші ціни доби | дані `data/tariffs.json` | лише файл; код не змінюється, укладені договори зберігають свою ціну |
