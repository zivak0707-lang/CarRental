# Журнал рішень стандарту CarRental

## ЖР-001. Гроші округлюємо один раз на підсумку документа

Дата: 09.11.2026. Статус: Прийнято.

**Контекст.** Політики `VipPricingPolicy` і `DiscountPricingPolicy` округлювали кожну позицію, а `RentalTotalCalculator` — підсумок. Для малих сум результат залежав від кількості рядків.

**Варіанти.**

- Округлювати кожну позицію: сума рядків завжди збігається з чеком, але похибка росте з кількістю рядків.
- Округлювати лише підсумок: одна точка, найменша похибка, проміжні суми показують без округлення.

**Рішення.** Округлюємо лише підсумок документа через `Money.RoundToKopecks` з `MidpointRounding.AwayFromZero`. Виняток — вартість доби `DailyCostFor`, бо це опублікований клієнтові тариф (X-05).

**Наслідки.** Три позиції по 0,045 грн дають 0,14, а не 0,15; це фіксує тест `TotalOf_ThreeSmallLines_RoundsOnceOnDocumentTotal`. Прямий `Math.Round` для `decimal` заборонено аналізатором RS0030.

## ЖР-002. Ім'я кінця інтервалу в ReservationDay

Дата: 09.11.2026. Статус: Прийнято.

**Контекст.** Правило D-16 вимагає виключного кінця інтервалу. Поле `ReservationDay.EndDate` вже так працює, але ім'я про це не каже; варіантом було перейменування на `EndDateExclusive`.

**Варіанти.**

- Перейменувати на `EndDateExclusive`: точно, але в предметній мові прокату такого терміна немає.
- Лишити `EndDate`, а виключність закріпити контрактом: XML-коментарем, правилом X-03 і тестами.

**Рішення.** Лишаємо `EndDate`, бо для працівника прокату це дата повернення автомобіля, у яку доба вже не оплачується. Суфікс `Exclusive` обов'язковий лише для нових інтервалів без такого предметного значення.

**Наслідки.** Ім'я лишається зрозумілим для предметної області, а межу гарантує обчислення `Days` і тести. Якщо в моделі з'явиться інтервал, де кінець входить, рішення переглянемо.
