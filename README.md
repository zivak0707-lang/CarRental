# CarRental

Консольний застосунок обліку прокату автомобілів філії (СР3, варіант № 7).
Автор: Сергій Зівак, група 471, КІСІТ.

## 1. Призначення

Застосунок веде бронювання, видачу, повернення і скасування оренд автомобілів,
рахує вартість прокату зі штрафом за запізнення та будує звіт «Зайнятість автопарку».

## 2. Можливості

| Пункт меню | Сценарій |
|---|---|
| 1 | UC-01 Забронювати автомобіль |
| 2 | UC-02 Видати автомобіль |
| 3 | UC-03 Закрити оренду (розрахунок прокату і штрафу) |
| 4 | UC-04 Скасувати бронювання |
| 5 | UC-05 Знайти оренди за станом, клієнтом, номером |
| 6 | UC-06 Звіт «Зайнятість автопарку» на дату |

Правило розрахунку: доба — розпочаті 24 години; пільга 60 хвилин;
штраф — 50 % ціни доби за кожну розпочату добу запізнення.

## 3. Вимоги

- .NET SDK 8.0 або новіший;
- Windows, Linux або macOS.

## 4. Запуск

```
dotnet build -c Release
dotnet test -c Release
dotnet run --project src/CarRental.ConsoleApp
```

Дані читаються з теки `data/` (JSON), журнал пишеться у `logs/carrental.log`.

## 5. Перевірка якості локально

Та сама перевірка, що й у конвеєрі CI:

```
dotnet format --verify-no-changes && dotnet build -c Release -warnaserror && dotnet test -c Release /p:CollectCoverage=true /p:Threshold=70 /p:ThresholdType=line
```

Покриття бібліотеки логіки (Domain + Application): рядки 98,6 %, гілки 81,8 %.

## 6. Конвеєр CI

`.github/workflows/ci.yml` запускається на кожен push і pull request у `main`:
отримання коду, відновлення залежностей, перевірка форматування, складання
без попереджень, тести з покриттям, поріг рядкового покриття 70 %, збереження звіту.

## 7. Структура

```
src/CarRental.Domain          правила предметної області
src/CarRental.Application     сценарії використання
src/CarRental.Infrastructure  JSON-сховище і журнал у файл
src/CarRental.ConsoleApp      меню і композиційний корінь
tests/CarRental.Tests         модульні та архітектурні тести
data/                         демонстраційні дані
docs/                         специфікація, архітектура, рішення
```
