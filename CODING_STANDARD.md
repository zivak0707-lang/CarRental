# Стандарт кодування проєкту CarRental

## 1. Загальні положення
1. Мова коду — C#, платформа .NET 8.
2. Мова ідентифікаторів — англійська; мова коментарів — українська.
3. Стандарт діє на весь код у CarRental.Core та CarRental.App.
4. Дотримання правил перевіряється автоматично: .editorconfig, аналізатори Roslyn і StyleCop.

## 2. Іменування

| Сутність | Конвенція | Приклад | Антиприклад |
|---|---|---|---|
| Клас, запис | PascalCase, іменник | `RentalLine` | `rentalline` |
| Інтерфейс | I + PascalCase | `IRentalRepository` | `Repository` |
| Метод | PascalCase, дієслово | `CalculateTotal` | `calc` |
| Властивість | PascalCase, іменник | `DailyRate` | `GetDailyRate` |
| Приватне поле | `_` + camelCase | `_lines` | `m_Lines` |
| Локальна змінна | camelCase | `totalAmount` | `ta` |
| Константа | PascalCase | `MaxRentalDays` | `MAX_DAYS` |
| Перелічення | PascalCase, однина | `RentalStatus` | `RentalStatuses` |

## 3. Форматування
1. Відступ — 4 пробіли; табуляція заборонена.
2. Довжина рядка — не більше ніж 100 символів.
3. Фігурні дужки — стиль Allman, обов'язкові навіть для однієї інструкції в тілі `if`.
4. Між членами класу — рівно один порожній рядок.
5. Директиви `using` — на початку файлу, системні перші, невживані видаляються.
6. Простір імен — файлового рівня (`namespace X;`).
7. Кодування файлів — UTF-8, обов'язковий порожній рядок у кінці файлу.

## 4. Коментарі та документація
Коментар пояснює «чому», а не «що». Код не дублюють словами.

```csharp
// погано: коментар переказує код
// збільшуємо лічильник на одиницю
count = count + 1;

// добре: коментар пояснює причину рішення
// прокат тарифікується за повну добу, тому округлюємо вгору
days = Math.Ceiling(rawHours / 24m);
```

Публічні члени бібліотеки `CarRental.Core` документують тегом `<summary>`.

## 5. Структура проєкту
1. Логіка предметної області — у `CarRental.Core`, введення й виведення — у `CarRental.App`.
2. Один публічний тип — один файл, ім'я файлу збігається з іменем типу.
3. Порядок членів класу: константи → поля → конструктори → властивості → публічні методи → приватні методи.

## 6. Правила комітів
Повідомлення у форматі Conventional Commits: `тип: коротка суть`.

| Тип | Коли вживають |
|---|---|
| feat | нова можливість |
| fix | виправлення дефекту |
| docs | документація |
| chore | інфраструктура |
| style | форматування |

## 7. Правила, закріплені машинно

| Пункт стандарту | Механізм перевірки | Правило |
